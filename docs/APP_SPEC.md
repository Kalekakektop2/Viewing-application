**Платформа MVP:** только Windows.

---

## 1. Продукт

Игровой **оверлей поверх окна игры**. По горячей клавише игрок выделяет область экрана, задаёт вопрос (или нет) и получает ответ Vision-ИИ: что на скрине, как скрафтить, где найти — без Alt+Tab в Wiki.

**Охват игр:** без приоритета конкретной игры. ИИ должен стараться понимать **любые** игры (песочницы, выживалки, заводские симы, моды и т.д.).

---

## 2. Появление и поведение оверлея

| Правило | Решение |
|--------|---------|
| Когда виден | Только после нажатия комбинации клавиш |
| Положение | Всегда поверх игры (overlay) |
| Горячая клавиша по умолчанию | `Alt+E` |
| Смена бинда | Да, в настройках |
| Захват экрана | **Только** область, которую выделил игрок (не весь экран принудительно) |
| После ответа | Оверлей **остаётся** |
| Закрытие | Клик **в любое место вне** оверлея |
| Диалог | Да: несколько уточняющих вопросов по той же сессии/скриншоту |

---

## 3. Ввод и быстрые действия

1. Горячая клавиша → режим выделения области.
2. После выделения — оверлей со **строкой ввода**.
3. Под строкой ввода — **отдельные кнопки** направлений:
   - «Что это?»
   - «Как скрафтить?»
   - «Где найти?»
4. Если **нет** текста в строке и не выбрана иная логика — по умолчанию ответ: **что это + как скрафтить**.
5. Можно отправить скрин «как есть» или с произвольным вопросом.

### Детализация ответа

Переключатель **Кратко / Расширенно** влияет не только на длину, но и на **формат**:

- **Кратко** — лаконично: название, 1–2 строки сути, короткий список (ингредиенты / биом / дроп).
- **Расширенно** — подробный гайд: шаги, цепочка, альтернативы, скрытые детали.

**MVP ответа:** достаточно **текста**. Визуальное дерево крафта не обязательно.

### Опционально: «Сгенерировать фото»

Кнопка быстрого действия: сгенерировать иллюстрацию (например, схему/предмет).  
**Обязательно** предупредить игрока, что генерация может занять заметное время.

## 4. ИИ, игра, подсказки

| Тема | Решение |
|------|---------|
| Модель | Любая **бесплатная** vision-модель, достаточная по качеству (пример: **Gemini**) |
| Определение игры | ИИ **угадывает** игру по скриншоту |
| Низкая уверенность | Предупредить: «ИИ может ошибаться именно по этой игре» |
| Память игры в сессии | Пока игрок в той же игре — **не спрашивать название каждый раз**; удерживать контекст игры в сессии |
| OCR / UI | Читать **подсказки** (тултипы, названия, хинты на экране), не только «голый» вид предмета |
| Промпт | Динамически: вопрос / кнопки + уровень детализации + контекст игры + (при наличии) OCR |

---

## 5. Кэш

- Желателен **кэш** частых/банальных предметов, чтобы снизить задержку.
- Пример: «Дерево» в Minecraft — не гонять vision каждый раз, если уже есть надёжный ответ.
- Небанальные/модовые/неуверенные случаи — снова в модель.

*(Детали ключа кэша: hash кропа + id/имя предмета + игра + тип вопроса — на этапе реализации.)*

---

## 6. Приоритеты качества (по важности)

1. **Удобный интерфейс** оверлея  
2. **Точность** ответов  
3. **Задержка** (захват + ответ + кэш)

---

## 7. Полноэкран и античит

Учитывать с самого начала (исследование + честные ограничения в UI):

- оконный / borderless / exclusive fullscreen;
- возможные конфликты overlay и hotkeys;
- античит (Vanguard и аналоги) — документировать риски; не обещать работу там, где overlay запрещён.

## 9. Основной пользовательский поток

```
Alt+E (или свой бинд)
  → выделить область
  → оверлей: ввод + кнопки (что / крафт / где) + Кратко|Расширенно
  → (опц.) OCR подсказок + угадывание игры
  → кэш? → ответ : запрос к vision-модели
  → текст в оверлее; можно продолжить диалог
  → (опц.) «Сгенерировать фото» + предупреждение о времени
  → клик вне оверлея → закрыть
```
